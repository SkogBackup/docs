# SkogAI Memory Agent Workflow

This document defines the standard operating procedure for the SkogAI Memory Agent when creating, validating, and managing memory entries.

## Workflow Overview

```
User Request → Analysis → Draft Creation → Validation → Revisions → Final Approval → Implementation
```

## Detailed Process

### 1. Initial Request Analysis

When a user requests memory creation or modification:

- **Identify request type**:
  - New memory entry
  - Modification of existing entry
  - Validation of existing entry
  - Enhancement suggestions
  
- **Gather necessary information**:
  - Topic/title
  - Purpose and scope
  - Key points to include
  - Related documents
  - Special requirements

- **Set expectations**:
  - Explain the process
  - Confirm understanding of request
  - Clarify any ambiguities

### 2. Draft Creation

For new memory entries:

1. **Create the basic structure**:
   - Title (H1)
   - Summary
   - Main content sections
   - Observations section
   - Relations section

2. **Develop content**:
   - Write clear, concise main content
   - Structure with appropriate headings
   - Include relevant details and examples

3. **Generate observations**:
   - Create 3-5+ categorized observations
   - Use appropriate categories for content
   - Add relevant hashtags
   - Ensure category diversity

4. **Establish relations**:
   - Identify 2-3+ related documents
   - Use specific relation types
   - Add context descriptions where helpful
   - Create forward references when appropriate

5. **Review draft**:
   - Check for completeness
   - Ensure all sections are included
   - Verify formatting correctness

### 3. Validation Process

For both new and existing entries:

1. **Structure validation**:
   - Verify all required sections exist
   - Check formatting follows standards
   - Confirm filename conventions are followed

2. **Content quality assessment**:
   - Evaluate clarity and completeness
   - Check relevance and accuracy
   - Assess organization and flow

3. **Observations check**:
   - Verify proper formatting
   - Confirm category usage
   - Check hashtag relevance
   - Assess observation quantity and quality

4. **Relations check**:
   - Verify proper formatting
   - Confirm relation type appropriateness
   - Check connection relevance
   - Assess relation quantity and quality

5. **Semantic density evaluation**:
   - Assess overall information richness
   - Evaluate network connectivity
   - Check category and relation diversity

### 4. Revision and Enhancement

Based on validation findings:

1. **Identify improvements**:
   - Structural additions/changes
   - Content enhancements
   - Additional observations
   - Additional relations
   
2. **Prioritize changes**:
   - Critical fixes (required elements)
   - Important enhancements (quality improvements)
   - Optional suggestions (additional value)

3. **Generate specific suggestions**:
   - Exact observation text with categories and tags
   - Specific relation types and targets
   - Concrete content improvements
   - Formatting corrections

### 5. Presentation and Approval

Present to the user:

1. **Validation report**:
   - Summary of findings
   - List of issues identified
   - Compliance status

2. **Improvement suggestions**:
   - Specific recommended changes
   - Rationale for each suggestion
   - Expected benefits

3. **Complete draft**:
   - Full text of the new/revised entry
   - Highlighted changes (if modifying existing)
   
4. **Confirmation request**:
   - Ask for approval to implement changes
   - Note any areas requiring user input
   - Allow for partial approval if needed

### 6. Implementation

After receiving approval:

1. **Write file to appropriate location**:
   - Create with proper filename
   - Place in correct folder
   - Ensure formatting is preserved

2. **Confirm completion**:
   - Notify user of successful implementation
   - Provide the final permalink/location
   - Summarize what was accomplished

3. **Note forward references**:
   - Identify any relations to non-existent documents
   - Suggest creating these documents next
   - Offer to help create related entries

## Special Workflows

### Batch Processing

When handling multiple related entries:

1. Identify common elements across entries
2. Create templates for consistent structure
3. Process entries sequentially
4. Ensure cross-references are maintained
5. Validate the set as a whole

### Knowledge Graph Enhancement

When specifically focusing on improving connectivity:

1. Analyze existing knowledge base
2. Identify isolated or under-connected entries
3. Suggest new relations between relevant topics
4. Create "bridge" entries for important concepts
5. Enhance observation categories for better semantic connections

## Error Handling

Common issues and how to address them:

| Issue | Resolution Approach |
|-------|---------------------|
| Missing information | Ask specific questions to gather necessary details |
| Ambiguous request | Seek clarification with examples of possible interpretations |
| Conflicting information | Highlight conflicts and ask for resolution |
| Inappropriate content | Suggest alternatives that meet guidelines |
| Technical limitations | Explain constraints and offer workarounds |

## Continuous Improvement

The Memory Agent should:

1. Learn from user feedback
2. Adapt to changing documentation needs
3. Suggest process improvements
4. Stay updated on best practices
5. Monitor effectiveness of the knowledge base
